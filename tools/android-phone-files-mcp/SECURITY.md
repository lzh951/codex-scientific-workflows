# Security

This project exposes phone files through MCP. Treat it as a privileged local-device tool.

## Never Publish

- Android owner token
- Live public relay URL
- Real device ID
- Phone screenshots containing tokens, URLs, or file names
- ADB logs containing private file paths
- `.env` files

## Recommended Defaults

- Use a strong owner token generated by the app.
- Restrict the relay to one `PHONE_DEVICE_ID`.
- Restrict the relay to one `PHONE_OWNER_TOKEN`.
- Use HTTPS for any public MCP endpoint.
- Prefer a fixed private relay hostname over a temporary quick tunnel for long-running use.
- Keep destructive file tools off unless the user explicitly asks for the operation.

## Expected Access Boundary

The intended root is Android shared storage:

```text
/storage/emulated/0
```

The project is not designed to expose:

- system partitions
- app-private databases
- chat app internal data
- contacts
- SMS
- notifications
- other apps' private storage

## Public Relay Risk

A public relay URL plus a valid owner token can grant file access to the authorized storage root. Rotate the token and remove the relay if a URL or token is exposed.

## Reporting

Open an issue without secrets. Replace real values with placeholders such as:

```text
https://relay.example.com/d/phone-example/mcp
<owner-token>
```
